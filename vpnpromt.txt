Build a complete, production-ready native Android VPN application in Android Studio using Kotlin.

1. Core requirements

The application must use the provided "libbox.aar" library as its VPN/networking engine.

Do NOT replace "libbox.aar" with another VPN library.

The application must be a real Android VPN using:

- Android "VpnService"
- "libbox.aar"
- the native libraries included inside the AAR
- TUN interface
- Shadowsocks / Outline-compatible server configurations

The application must support ONLY Shadowsocks servers compatible with Outline.

Do NOT add support for:

- VLESS
- VMess
- Trojan
- Hysteria
- Hysteria2
- TUIC
- WireGuard
- SOCKS server configuration
- HTTP proxy server configuration
- Any other proxy protocol

The only server protocol exposed to the user must be Shadowsocks / Outline.

2. Server source

The server list must be loaded from this URL:

https://raw.githubusercontent.com/qatarvpn/vpnme/refs/heads/main/services.json

The JSON format is:

[
{
"name": "United States 1 🇺🇸",
"config": "ss://YWVzLTEyOC1nY206c2hhZG93c29ja3M@149.22.87.204:443#United States 🇺🇸"
},
{
"name": "United States 2 🇺🇸",
"config": "ss://YWVzLTEyOC1nY206c2hhZG93c29ja3M=@156.146.38.170:443#United States 🇺🇸"
}
]

Create proper Kotlin data models:

Server:

- name: String
- config: String

Use a robust JSON parser such as Kotlin serialization or Gson.

The application must download the server list asynchronously.

Never block the main UI thread.

Add:

- loading state
- successful loading state
- empty state
- network error state
- retry button

Cache the last successfully downloaded server list locally so the application can still display the previous server list if the server JSON cannot currently be downloaded.

3. Shadowsocks configuration

The "config" field contains an "ss://" URI.

Implement a proper Shadowsocks URI parser.

The parser must correctly handle:

- URL encoding
- Base64 encoding
- Base64 padding
- username/password-style Shadowsocks URI formats
- hostname/IP
- port
- fragment/name

Do NOT manually hard-code the server credentials.

Each server must be converted from the "ss://" URI into the appropriate configuration required by "libbox".

The application should validate the configuration before attempting to connect.

If a server configuration is invalid, show a clear error rather than crashing.

The VPN service must:

1. Request Android VPN permission.
2. Create the TUN interface.
3. Pass the TUN file descriptor to libbox.
4. Start the libbox service.

6. Properly stop and clean up the service when disconnected.
7. Handle network changes.
8. Handle Android lifecycle events.
9. Avoid leaking file descriptors.
10. Avoid crashing when the network changes.

10. Connection logic

The connect button must follow this logic:

IF VPN is disconnected:

1. Check that a server is selected.
2. Validate the Shadowsocks configuration.
3. Request VPN permission if necessary.
4. Start "QatarVpnService".
5. Create TUN.
6. Start libbox.
7. Update UI to Connecting.
8. When service successfully starts, update UI to Connected.

IF VPN is connected:

1. Stop libbox.
2. Stop the VPN service.
3. Close the TUN descriptor.
4. Update UI to Disconnected.

Prevent multiple simultaneous connection attempts.

Disable repeated taps while connecting/disconnecting.
